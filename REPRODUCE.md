# Reproducing the analysis

Every deposited file in `results/` is listed in `results/MANIFEST.csv` with the exact command
that produces it. This file gives the order. Verified against the deposited scripts
2026-11-04.

## 0. Environment

```
python -m venv venv && . venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 1. Data

Neither dataset is redistributed here.

- **ERP CORE visual P3** — download separately and place or symlink it at
  `data/erp_core_P3`, or set `ERP_CORE_P3_DATA` to wherever it lives.
- **ds006018** — OpenNeuro. Set `DOF_DS006018_DATA` to its root.

`data/` is git-ignored. Paths now default to locations inside the repository, so a fresh
clone needs no edits to `scripts/config.py`.

## 2. Main pipeline

The pseudotrial contrast is produced by one script with flags. The output suffix encodes the
flags, which is why several files share a stem:

```
python scripts/run_phase013.py --config config4 --k 1000 --out results
python scripts/run_phase013.py --config config4 --k 1000 --clean-pseudo   --out results
python scripts/run_phase013.py --config config4 --k 1000 --resample 500   --out results
python scripts/run_phase013.py --config config4 --k 1000 --targets-only   --out results
python scripts/run_phase013.py --config config2 --k 1000 --out results
```

Each run writes four files: `phase013_dbeta_<suffix>.csv`,
`phase013_interaction_<suffix>.csv`, `phase013_persubject_<suffix>.csv` and
`phase013_marginal_r2_<suffix>.csv`, where `<suffix>` is
`<config>_K<k>[_targets][_clean][_rs<hz>]`.

**Placement counts.** `--k 1000` is the number of surrogate placements *attempted* per
participant, not the number achieved. The median achieved is 1,000, but the minimum is 594
in the primary dataset and 202 in independent validation, and a participant is retained only
at `--min-pseudo 200` achieved placements or more. Reported participant counts (28 and 84)
follow from that gate.

## 5. Known gaps

- **`scripts/17_overlap_audit.py` does not run.** Three independent faults are documented in
  its module header. The deposited `results/overlap_audit_erp_core_config4.csv` was not
  produced by it, and its column schema differs, so that result currently has no runnable
  provenance in this repository. It must be repaired, replaced with the code that actually
  produced the CSV, or withdrawn along with the figures that rest on it.
- **`results/legacy/`** holds four files from an earlier version of `run_phase013.py` whose
  suffix lacked the `_K<k>` component. They cannot be regenerated by the current pipeline.
  See `results/legacy/README.md`; nothing in `scripts/` reads them.
- **Dead keys in `scripts/config.py`.** The `FILES` entries `interelectrode_all`,
  `interelectrode_same` and `interelectrode_cross` route into `logs/`, but
  `09_interelectrode_validation.py` writes those files directly to its `--out` directory and
  never uses the keys. The keys are unused.
